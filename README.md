# 个人工作看板

一个单文件的个人看板，把《将工作可视化》（Dominica DeGrandis，*Making Work Visible*）的方法用在日常工作和个人项目上：

- **周看板**：计划，把任务和子项目安排到具体哪一天
- **日看板**：执行，用 🍎 番茄钟推进当天挑出来的事
- **月历**：记录关键时间

整个产品就是一个 `index.html`，不需要安装，也不需要服务器。用浏览器打开就能用，也可以部署到 GitHub Pages，在电脑和手机之间同步。

---

## 为什么做这个

书里把拖慢工作的原因归纳为五个“时间窃贼”，看板里分别有对应的处理方式：

| 时间窃贼 | 看板里的对策 |
| --- | --- |
| 在制品过多 | “进行中”设上限（默认 3），满了不能再拉新任务 |
| 未知的依赖 | 单独的“等待中”列，记录在等谁，超过 7 天标红 |
| 计划外工作 | 任务可以标记为“插单”，统计插单占比 |
| 优先级冲突 | 周看板把任务排到具体日子，日看板只做挑进来的事 |
| 被忽视的工作 | 停滞 21 天预警，30 天判为僵尸任务，逐件处理 |

另一个目标，是让总被工作挤掉的**个人项目**也能稳定启动。

## 功能一览

### 周看板

- **周节奏条**：一周七天，每天显示安排了几件、完成了几件，以及当天的关键时间。点日期进入日看板，把任务卡拖到日期上就是安排到那天。
- **统计区**：
  - **工作、个人**：用方块矩阵显示“完成 / 目标”件数，一格代表一件。
  - **僵尸任务**：一次只显示一件，从停滞最久的开始，只有两个按钮：**做十分钟**、**放弃**。
- **五列看板**：项目清单、待办、进行中、等待中、完成。
  - **项目清单**：每个项目有进度环和子项目清单，项目和子项目都可以拖动排序，整列可以向左收起。
  - **任务卡**：可以通过“安排到…”选择安排在本周哪一天。
- **分类筛选**：工作 / 个人。

### 日看板

- **计划与实际**：两行 🍎 对比计划时长和实际时长，1 🍎 = 20 分钟。
- **当天清单**：只显示你安排或挑进来的任务。
- **挑选区**：从待办和进行中的任务里挑，分为“⚡ 简单”“困难重要”“普通”三组，也可以直接新建任务放进当天。
- **计时**：▶ 20 分钟番茄钟。
- **补记与撤回**：点灰苹果补记到那一个，点红苹果撤回，也可以用 +🍎 补记。
- **困难重要的任务**：显示累计启动次数和每次启动的记录，目标是“启动一次就算赢”。
- **简单任务动效**：带光效和动画，让人想马上做掉；完成时会弹出彩色碎片。

### 月历

- 月视图里点任意一天，就能添加关键时间（时间可填可不填，再写一句内容）。
- 关键时间会同时显示在周节奏条和日看板顶部。

### 其他

- 浅色 / 深色主题跟随系统。
- 手机端适配：看板改为标签切换，一次看一列；弹窗改为底部抽屉。
- 备份 / 导入：把全部数据导出为文本，或从文本恢复。

## 快速开始

### 方式一：本地打开

1. 下载 `index.html`。
2. 用 **Chrome** 或 **Edge** 打开。
3. 第一次打开会看到示例数据，点“清空”就能开始使用。

数据保存在当前浏览器里。换浏览器、使用无痕模式或清理缓存后，会看不到之前的数据。

### 方式二：部署到 GitHub Pages

1. 新建一个 GitHub 仓库，把 `index.html` 上传到根目录。
2. 打开仓库的 **Settings → Pages**：
   - Source 选 **Deploy from a branch**
   - 分支选 `main`，目录选 `/ (root)`
   - 点 Save
3. 1 到 2 分钟后，访问 `https://<你的用户名>.github.io/<仓库名>/`。

## 电脑与手机同步（GitHub Gist）

GitHub Pages 只能放静态网页，本身不保存你在页面上的操作。想在多台设备之间同步，可以把数据存进你 GitHub 账号下的一个**私密 Gist**。

### 第一次设置（电脑）

1. 打开看板，点顶部的 **同步**。
2. 点弹窗里的“在 GitHub 生成一个密钥”，会打开 GitHub 页面，gist 权限已经帮你勾好：
   - Expiration（有效期）可以选 No expiration
   - 点页面最下方的 **Generate token**
3. 复制生成的密钥（以 `ghp_` 开头），粘贴回看板，点 **连接**。
4. 右上角显示“已同步到 GitHub”，就说明成功了。

### 在手机上连接

1. 用手机打开同一个网址，点 **同步**。
2. 粘贴**同一个密钥**，点 **连接**。
3. 如果手机上已经有自己的数据，会让你选择用哪一份，一般选“用 GitHub 上的”。

### 同步规则

- 每次改动约 2 秒后自动上传。
- 打开页面、切回页面时自动拉取最新数据；页面开着的时候，每分钟也会检查一次。
- 两边都有改动时，以**最后保存**的一方为准，所以尽量不要在两台设备上同时编辑。

### 关于密钥安全

- 这个密钥只勾选了 `gist` 权限，不能读写你的代码仓库。
- 它只保存在你自己设备的浏览器里，不会写进网页代码，所以仓库公开也不会泄露。
- 不再使用，或担心泄露时，可以在 GitHub 的 **Settings → Developer settings → Personal access tokens** 里删除它，再生成一个新的重新连接。

## 使用建议

1. **周一**：在周看板把本周要做的任务、子项目“安排到…”具体日子。
2. **每天开始**：进入当天的日看板，确认清单，从挑选区补上当天要做的事，先做一件 ⚡ 简单的。
3. **执行**：点 ▶ 20 分钟开始专注；困难的事不求做完，先启动一次。
4. **每周回顾**：看一眼统计区和僵尸任务卡：
   - 插单是不是太多
   - “等待中”有哪些该去催了
   - 僵尸任务要么做十分钟，要么放弃

## 计算口径

| 指标 | 口径 |
| --- | --- |
| 周目标 | 本周七天内安排过的任务数，按工作 / 个人分开统计 |
| 周完成 | 周目标里已经完成的任务数 |
| 最后一次动过 | 以下操作中最近的一次：换列、计时或补记、安排到某天、勾选关联的子项目、编辑任务 |
| 停滞预警 | 待办或进行中的任务，距最后一次动过 ≥ 21 天 |
| 僵尸任务 | 待办或进行中的任务，距最后一次动过 ≥ 30 天 |
| 等待超时 | 在“等待中”停留 ≥ 7 天 |
| 插单占比 | 本周新建的任务里，标记为插单的比例 |
| 计划 🍎 | 当天清单里所有任务的计划数相加。默认值：简单 1 个、普通 2 个、困难重要 1 个，可以在日看板修改 |
| 实际 🍎 | 当天计时和补记的总分钟数 ÷ 20 |
| 项目进度 | 已完成的子项目数 ÷ 子项目总数 |

## 常见问题

**电脑上改了，手机上看不到？**
先看右上角的同步状态。如果显示“仅保存在本机”，说明这台设备还没连接同步，点“同步”粘贴密钥即可。如果已经连接，切回页面或刷新一下，就会拉取最新数据。

**换了新电脑，或者浏览器数据被清掉了？**
如果之前连接过同步，重新粘贴密钥就能恢复。没连接过的话，只能从之前的“备份”导入。

**手机上为什么不能拖动？**
手机浏览器不支持拖动操作。换列用卡片上的 ‹ › 按钮，安排日期用“安排到…”。项目和子项目的排序需要在电脑上调整。

**为什么推荐 Chrome 或 Edge？**
Safari 对本地打开的 HTML 文件限制较多，数据可能保存不了。部署到 GitHub Pages 后，各个浏览器都能正常使用。

## 已知限制

- 两台设备同时编辑时，后保存的一方会覆盖前者。
- 手机上不支持拖动排序。
- 计时只能在“今天”进行，过去的日期只能补记 🍎。
- 计划 🍎 数跟着任务走，不能按天分别设置。

## 技术说明

- 单个 HTML 文件，原生 JavaScript，不依赖任何框架。
- 字体：Noto Serif SC、Noto Sans SC、JetBrains Mono（通过 Google Fonts 加载，加载不了时使用系统字体）。
- 本地存储：浏览器 `localStorage`，键名为 `personal-kanban-v2`。
- 同步：GitHub REST API（Gists），数据存在私密 Gist 的 `kanban.json` 文件里。
- 系统开启“减少动态效果”时，页面上的动画会自动关闭。
